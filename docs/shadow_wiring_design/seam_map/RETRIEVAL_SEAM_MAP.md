## 2. Seam Analysis & Evaluated Insertion Points

### Seam 1: `Retriever.answer` Post-Processing Wrapper (RECOMMENDED)
- **File**: `retrieval.py`
- **Symbol**: `Retriever.answer`
- **Line Range**: 93–109
- **Input Contract**: `(question: str, current_case_modality: Optional[str] = None)`
- **Output Contract**: `legacy_response: str`
- **Allowed Call Direction**: Legacy executes first -> Result stored -> Shadow process invoked in isolated `try...except` block -> Legacy result returned unmutated.
- **Failure Behavior**: If shadow processing throws an exception or times out, the exception is logged to shadow audit/telemetry, and the original `legacy_response` is returned immediately.
- **Side-Effect Risk**: Zero. Shadow execution is fully isolated and its return value is discarded.
- **Status**: **RECOMMENDED**

### Seam 2: `Retriever.answer` Pre-Processing Entry (REJECTED)
- **File**: `retrieval.py`
- **Symbol**: `find_entry_concepts` / start of `Retriever.answer`
- **Line Range**: 94–96
- **Reason for Rejection**: Executing shadow before legacy retrieval creates a risk where shadow failure could block or delay the execution of the primary legacy path.

### Seam 3: `Retriever._compose` Internal Mutation (REJECTED / UNSAFE)
- **File**: `retrieval.py`
- **Symbol**: `Retriever._compose`
- **Line Range**: 111–146
- **Reason for Rejection**: Inserting shadow logic inside `_compose` directly alters the prompt construction and LLM client call, violating the invariant that legacy response generation remains untouched.

## 3. Legacy Payload & Contract Invariants

To ensure zero regression:
1. **Request Invariance**: `Retriever.answer(question, modality)` signature remains unchanged.
2. **Response Invariance**: Return value is strictly the `str` generated by legacy logic.
3. **Exception Invariance**: Any exception thrown by legacy retrieval (e.g. Neo4j connectivity failure) propagates exactly as before; shadow wrapper does not mask legacy errors.
4. **Latency Measurement**: Shadow execution latency is tracked independently in telemetry metrics (`shadow_execution_ms`).
