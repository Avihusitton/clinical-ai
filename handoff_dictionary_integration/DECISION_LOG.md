# יומן החלטות ארכיטקטוניות (Decision Log)

החלטות אלו מבוססות על הביקורת של הארכיטקט פייבל, שמטרתן למנוע שגיאות נפוצות במערכות RAG רפואיות/קליניות:

## 1. איסור הרעלת מצב שקטה (No Silent State Poisoning)
**החלטה:** עוגן זמן (Time Anchor) מחלחל לפסקאות הבאות רק בתוך תמליל טיפול, ולא ממסמכי שיטה.
**סיבה:** אם אלגוריתם נותן בטעות "תאריך טיפול" לפסקה ששייכת לתיאוריה הכללית, הפסקה תישלף כתגובה ל"מה קרה באותו תאריך?" - דבר שיוביל להלוסינציה של ה-LLM בייעוץ למטפל.

## 2. הפרדת מועמדות מקשר אמיתי (HAS_CANDIDATE vs LINKED_TO)
**החלטה:** אלגוריתם דטרמיניסטי לעולם לא יצור קשר שמיש למודל (`LINKED_TO`), אלא רק מועמדות (`HAS_CANDIDATE`).
**סיבה:** המילה "דיכאון" יכולה להופיע כ- "הוא לא בדיכאון". איתור טקסטואלי יתפוס אותה. רק LLM יכול להבין שלילת משמעות ולקבוע האם ההקשר הקליני מצדיק יצירת קשר אמיתי. ה-Retrieval קורא רק מ-`LINKED_TO`.

## 3. שער קשיח ל-De-identification
**החלטה:** בלי מפתח LLM פעיל, המערכת קורסת ולא מכניסה את המסמך לגרף.
**סיבה:** מניעת מצב שבו גרסת בדיקה בטעות קוראת קבצי מטופלים אמיתיים ומכניסה שמות פרטיים למסד נתונים, דבר המהווה עבירה על חוקי הגנת פרטיות רפואיים.

## 4. מעקף ל-Vector Database
**החלטה:** לא נעשה שימוש ב-Pinecone/Embeddings עבור איתור דלת הכניסה בשאילתות.
**סיבה:** כאשר המילון הוא קטן ומבוקר (מאות מושגים), Embedding יעלה False Positives של מושגים קרובים סמנטית (למשל, "חרדה" במקום "פחד נטישה"). שימוש בהתאמה מורפולוגית לעברית מדויק יותר למילון קליני נוקשה.
